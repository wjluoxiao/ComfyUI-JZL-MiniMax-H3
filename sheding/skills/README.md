# JZL Skill 设定词管理

这里集中管理 MiniMax-H3 导演台的**强化层设定词**（skill）。

## 一、为什么要分层

导演台的系统提示词由四层拼成，**优先级从低到高**：

| 层 | 内容 | 谁能改 |
|---|---|---|
| ① 强化层 | 怎么理解故事 / 怎么分情节 / 补哪些细节 / 怎么设计动作 | **skill（内置或自定义）** |
| ② 风格层 | 叙事重心、色调光线、摄影语言、导演语法 | 内置 8 风格 或 自定义风格 skill |
| ③ 偏好层 | 景别/运镜/切镜/转场/字数 + 自定义润色规范 | 节点面板 |
| ④ 强制层 | 六段 Ref2VA 输出格式、调度指令 JSON、时间戳铁律 | **不可改，永远最后生效** |

所以：换 skill 只会改变"怎么把故事写得更好"，**不会破坏输出格式**。
故事扩写模式没有第 ④ 层（扩写只出正文，不涉及分镜格式）。

## 二、目录结构

```
sheding/skills/
├── README.md              本文件
├── mode/                  拆解 skill（故事拆解模式 + 仅提示词输出 共用）
│   └── 10-标准拆解.md
├── expand/                扩写 skill（故事扩写模式）
│   └── 10-标准扩写.md
└── style/                 内置故事风格（8 个）
    ├── 00-禁用风格.md … 07-歌神舞台.md      ← 中文原文
    └── en/                                  ← 英文译文（同名配对）
        └── 00-禁用风格.md … 07-歌神舞台.md

<ComfyUI>/user/jzl_skills/  用户导入的 skill（不会随插件升级丢失）
├── mode/
├── expand/
└── style/
```

用户导入的 skill 只出现在节点面板「自定义 skill」的下拉里；内置的不受影响。

> 下拉里的风格名用的是**中文文件名**（它就是存进工作流的取值），
> 选「英文 [EN]」输出时，代码会自动去 `style/en/` 找同名译文。
> 所以中文名 + 英文译文是**一个风格的两份稿子**，不是两个风格。

## 三、文件格式

**`.txt` 与 `.md` 完全等价**，两种都支持（`.markdown` 也放行）：

| 位置 | 支持扩展名 | 说明 |
|---|---|---|
| 插件内置 `sheding/skills/<kind>/` | `.md` / `.txt` / `.markdown` | 随插件发布；用 `.md` 只是方便写注释与标记 |
| 用户导入 `ComfyUI/user/jzl_skills/<kind>/` | `.txt` / `.md` / `.markdown` | 导入时**保留原扩展名**（`.txt` 存成 `.txt`） |

编码：UTF-8（含 BOM）与 **GBK** 都能自动识别，直接把手写的 `.txt` 丢进目录也能被读出来。

### 3.0 中英文双语（`<!-- JZL:LANG:ZH -->` / `<!-- JZL:LANG:EN -->`）

提示词语言选「英文 [EN]」时，skill 与风格都按语言取段。规则只有两条：

| 文件里有没有 `JZL:LANG:` 标记 | 英文模式怎么用 |
|---|---|
| **没有**（纯中文一份） | **原样整份使用**——英文模式下这份中文内容会原样进提示词（模型仍会按语言要求写英文正文，只是这份设定词本身是中文） |
| **有**（双语/纯英文一份） | 按标记切段：取 `EN` 段；只有 `ZH` 段时回退中文 |

所以自定义 skill 可以是：

- **纯中文**：什么都不用加，写正文即可；
- **纯英文**：什么都不用加，写英文正文即可；
- **双语**：用标记切成两段，各写一份（推荐，内置文件就是这么写的）：

```markdown
<!-- JZL:LANG:ZH -->
（中文设定词）

<!-- JZL:LANG:EN -->
（English version of the same rules）
```

> 内置 8 个故事风格的英文译文放在 `style/en/`，与中文文件**同名**配对；
> 少一个译文不会报错，只会让那个风格在英文模式下回退成中文原文。

### 3.1 拆解 skill（`mode/`）

用两个标记把文件切成「任务」和「执行规则」两段：

```markdown
# 我的拆解设定

<!-- JZL:TASK -->
（这一段进【任务】槽；不写则使用通用的任务描述）

<!-- JZL:RULES -->
（这一段进「第 3 步 执行时遵守」，也就是真正的拆解规则）
```

- 两个标记都可以省略；
- **只写了正文、没有标记** → 全文当「执行规则」，【任务】用通用一句话补齐。

### 3.2 扩写 skill（`expand/`）

直接写扩写规则正文即可。标记 `<!-- JZL:LANG:ZH -->` / `<!-- JZL:LANG:EN -->`
可以把中英文分开放（内置文件就是这么写的）；没有分语言标记时，整份文本对两种语言通用。

可用占位符（会被自动替换）：

| 占位符 | 含义 |
|---|---|
| `{EXPAND_WORDS}` | 目标字数 |
| `{LANG_NAME}` | 输出语言名 |
| `{Segment_Count}` | 分段数（拆解 skill 用） |
| `{Segment_Duration}` | 每段时长描述 |
| `{Detail_Length}` | 详细描述目标字数 |

未识别的占位符会原样保留，不会报错。

### 3.3 风格 skill（`style/`）

就是一份完整的「故事风格」正文，结构建议与内置风格一致：

```markdown
## 风格定位
推荐故事类型：…
一句话重心：…

## 核心原则
…

## 视觉风格 / 色调与光线 / 摄影语言 / 核心导演语法
…
```

英文译文的两条路：

- 在同一个文件里用 `<!-- JZL:LANG:EN -->` 加一段英文（单文件双语）；
- 或者放进 `style/en/同名文件.md`（内置 8 风格用的就是这条，中英各一个文件更好维护）。

## 四、怎么导入

节点面板 →「🎛️ 运行参数设置」→「运行模式」或「故事风格」→ 选「自定义 skill」→
点「导入」，选择本地的 `.txt` / `.md` 文件即可（浏览器上传，云机也能用）。

导入后文件名就是 skill 名（同名自动加 ` (2)`）。支持 UTF-8 / GBK 编码。

## 五、注意事项

- 内置 skill 不要改名（`10-标准拆解` / `10-标准扩写` / `00-…07-…`），否则会按"用户没选"回退到兜底文本；
- 改内置 `.md` 后重启 ComfyUI（或重新加载工作流）生效；
- 内置风格的英文译文在 `style/en/`，文件名必须与中文文件**完全一致**才会被配对；
- 强制格式层（`sheding/h3_shot_rules.py`）故意不放进 skills 目录：它是产物合规的底线，不提供覆盖入口。
