# MiniMax-H3 生成管理器 · 使用说明

> 一个节点完成 **剧本分段 → 参考调度 → 编码 → 采样 → 解码** 全流程；支持 ffmpeg 逐段落盘 / 自动合并。

---

## 一、快速上手

1. 添加节点 **JZL/MiniMax → `JZL - 🤖 MiniMax-H3短剧导演台Pro`**
2. 接好 **主模型 / CLIP / 视觉VAE / 音频VAE**（含视频或音频参考时必须接「音频VAE」）
3. 在 **📝 提示词** 框写故事 / 剧本（可用 `@` 引用素材），并在「📁 参考素材管理」配置素材
4. 设定参数后运行（「生成视频数量」默认「**剧情决定**」= LLM 按剧情时间线长度 ÷ 每段时长自动定段数；也可手动指定 1/2/3/4/6/9/12/16/20/26/32/40/48/56 段）

> 不接模型也能运行：只做剧本分段 + 调度，不采样解码。

---

## 二、运行模式

| 模式 | 什么时候选它 |
|---|---|
| **🛠️ 故事拆解模式** | 已有满意的故事，直接拆段生成视频（不改剧情、不新增对白） |
| **📚 故事扩写模式** | 故事太短，先扩写成丰满正文（纯文本，不生成视频） |
| **📝 仅提示词输出** | 只想先看拆解 + 增强后的提示词（纯文本，无需接模型） |
| **🪄 穿透生成模式** | 已有满意的拆解提示词，直接出片（跳过 LLM 拆解与增强） |

- 推荐流程：`📝 仅提示词输出` 调提示词 → 满意后切 `🪄 穿透生成模式` 出片。
- **输入要求**：拆解 / 扩写吃**自然语言故事**；含已拆解标签（`===H3_PROMPT===`、`[SHOT_START]`、`subject_definitions:`、`### Video_001` 等）会报错终止，请改用 `🪄 穿透生成模式`。
- **穿透 / 重拍只接受拆解产物**：需含 `[SHOT_START]…[SHOT_END]` 且每段含 `===H3_PROMPT===` 六段正文，格式不对直接终止。
- **穿透生成段数自动对齐**：`🪄 穿透生成模式` 一律按提示词里实际的 `[SHOT_START]` 段数生成，**「生成视频数量」设定被忽略**（不再因两者不一致而报错终止，也不会多生成空占位段），上限 60 段。日志会打印 `🔒 穿透生成：提示词实际 N 段，已忽略「生成M段」设定`。
- **逐段时长**：每段的 `**时长**：N`（英文 `**Duration**：N`）决定该段时长，中英文字段名都识别；缺失时回退节点「每段视频时长」。
- **时长强制约束（提示词必须落在时长内）**：系统提示词会把「每段视频时长」翻成一组硬预算——**镜头数硬上限、最后一镜的时间戳上限、按秒缩放的描述字数**。例如 5 秒一段 ⇒ 常规 2~3 镜、硬上限 6 镜、最大时间戳 4.2 秒、描述 220~350 字。若 LLM 仍然把内容排到时长之外，后端会**按比例把时间戳压回时长内**，并在日志打印
  `⚠️ 本段时长 5 秒但时间戳写到 18.5 秒（10 个时间戳）→ 已按比例压缩到 5 秒内`——看到这条说明模型没听话，**建议减少镜头或加长时长后重跑**，否则成片会是碎切。

### 运行模式下的 skill 选择

「🎛️ 运行参数设置 → 运行模式」里，每种模式下面还有一层可选设定：

| 模式 | 可选设定 | 说明 |
|---|---|---|
| 🛠️ 故事拆解模式 / 📝 仅提示词输出 | 内置 skill ／ 自定义 skill（下拉 + 📥 导入 + 👁 预览） | 决定**怎么理解故事、怎么分情节、补哪些细节**；两者共用同一批拆解 skill |
| 📚 故事扩写模式 | 内置 skill ／ 自定义 skill | 决定**按什么基调/重点扩写**；扩写不涉及输出格式与调度 |
| 🪄 穿透生成模式 | 严格对齐 ／ 自由模式 | 严格对齐=必须符合 `[SHOT_START]` + `===H3_PROMPT===` 格式；自由模式=跳过校验（有分段块按段数、没有就整段按 1 段） |

分层原则（**skill 改不了格式**）：

```
① 强化层（skill）  → ② 风格层（内置风格 / 自定义风格 skill） → ③ 偏好层（镜头偏好 / 自定义润色） → ④ 强制层（输出格式 + 调度 + 时间戳）
```

- ④ 永远最后生效、不可被 skill 覆盖，所以换 skill 不会破坏产物格式；
- 自定义 skill 存在 **`ComfyUI/user/jzl_skills/`**（`mode` / `expand` / `style` 三个子目录），插件升级不会丢失；
- 内置 skill 在 **`sheding/skills/`**，可当模板参考；格式写法见 `sheding/skills/README.md`；
- 内置风格的英文译文在 **`sheding/skills/style/en/`**（与中文文件同名配对），单语 skill 也能直接用；
- 导入支持 `.txt` / `.md`（UTF-8 或 GBK），同名会自动加 ` (2)`。

「故事风格」同样有两种来源：**内置风格**（8 个，勾选式宫格）或**自定义 skill**（下拉 + 导入 + 预览）。
自定义风格不会混进内置下拉，旧工作流的风格值不受影响。

> ⚠️ 故事风格**主要在开启「提示词增强」时才真正决定成片质感**——增强会把故事风格作为最高权重锚点，
> 逐句落到画面里；拆解阶段它只作导演视角参考，故事扩写阶段只作扩写基调。
>
> 「禁用风格」**不是增强开关**：它的意思是"不做风格侧重、纯按剧情"，拆解与增强仍会照常执行。

### 提示词语言（🤖 大语言模型配置 → 输出语言）

选「英文 [EN]」时，整条提示词链路都会切成英文——不只是要求模型写英文，**设定词本身也是英文**：

| 部分 | 中文模式 | 英文模式 |
|---|---|---|
| 系统提示词骨架 / 六段格式 / 调度指令 | 中文 | 英文 |
| 运行模式 skill（拆解 / 仅提示词 / 扩写） | 中文段 | 英文段（双语文件按 `JZL:LANG:EN` 取） |
| 故事风格（内置 8 个） | `style/*.md` | `style/en/*.md`（缺译文回退中文） |
| 🎯 镜头参数预设（景别/运镜/机位/切镜/转场/配乐/字数） | 中文 | 英文 |
| 自定义 skill（用户导入） | 单语文件原样使用 | 同左；双语文件取英文段 |

实测英文模式下整份系统提示词的汉字占比 <1%，剩下的都是**必须保留原样的东西**：
素材槽位名（`角色A` / `场景A` / `音色A`，必须和素材节点标题一字不差）、`<d>` 里的原台词、
用户自己写的中文故事、以及选项值原文引用。

> 自定义 skill 可以是**纯中文 / 纯英文 / 双语**，三种都支持；写法见 `sheding/skills/README.md`。

### 提示词增强（🤖 大语言模型配置 → 提示词增强）

一个复选框，只在「🛠️ 故事拆解模式 / 📝 仅提示词输出」下显示：

| 状态 | 行为 | 适用 |
|---|---|---|
| **关（默认）** | LLM 拆成分段提示词后直接生成（最快） | 绝大多数情况 |
| **开** | 拆解后再用 LLM 润色每段 `detailed_description`（耗时约翻倍；故事风格在这一步权重最高） | 追求画面质量 |

> 需要**完全跳过 LLM** 时用「🪄 穿透生成模式」，而不是关掉增强——穿透模式才是"不做任何 LLM 处理"的正确入口。
> 旧工作流里遗留的 `story_decompose=false` 会被自动修正为 `true`（后端日志会提示）。

### 各设置的作用范围

| 设置 | 🛠️ 拆解 | 📚 扩写 | 📝 仅提示词 | 🪄 穿透 |
|---|:---:|:---:|:---:|:---:|
| 故事风格 | 参考 | 基调 | 参考 | — |
| 🎯 镜头参数预设 | ✅ | ❌ | ✅ | — |
| 自定义润色规范 | ✅ | ❌ | ✅ | — |
| 运行模式下的 skill | 拆解 skill | 扩写 skill | 拆解 skill | 严格/自由 |

（拆解 = 拆解提示词；✅ = 直接控制产出；— = 不经过 LLM）

## 三、素材与参考调度

- 上限：图片 ≤9 / 视频 ≤3 / 音频 ≤3，总参考 ≤12（官方上限）
- 用 `@素材名` 引用，或由调度指令（`类型:槽位名`）自动匹配
- 生成路径**固定为多参考（REF2VA）**：图片 = 身份参考、音频 = 音色 / 配乐 / 念白参考（**严格使用你上传的音频文件**）；**不存在首尾帧 / 首帧（fl2va）路径**。视频未被引用时，视频与视频音轨端口自动关闭（避免音频误入音轨通道）
- 每段编码后打印**真实调用信息**（槽位名 = image N / Video N / Audio N），被跳过或未载入的参考不会出现
- 「🎯 参考元素切换」可在 **纯文本 / @引用着色** 间切换

### 📁 参考素材管理

缩略图（音频为试听键）固定在每张卡片最前；上传按钮随状态在「上传素材 / 替换素材」间切换；文件也可直接拖到面板或卡片缩略图上。

| 分区 | 卡片选项 |
|---|---|
| 🖼️ 图片 · 角色 | 编号 + 角色名 + 上传/替换素材 + 删除槽位 ／ 图片详细描述 |
| 🖼️ 图片 · 场景 | 编号 + 场景名 + 上传/替换素材 + 删除槽位 ／ 图片详细描述 |
| 🖼️ 图片 · 道具 | 编号 + 道具名 + 上传/替换素材 + 删除槽位 ／ 图片详细描述 |
| 🎬 视频 | 类型 + 编号 + 名称 + 详细描述 + 上传/替换素材 + 删除槽位 |
| 🎧 音频 · 角色音色 | 编号 + **指定角色名**（未指定 + 角色列表，角色改名/删除自动联动）+ 详细描述 + 上传/替换素材 + 删除槽位 |
| 🎧 音频 · 背景配乐 | 编号 + 名称 + 详细描述 + 上传/替换素材 + 删除槽位 |
| 🎧 音频 · 念白 | 同上 |

> **编号独立性**：图片三类、视频、音频三小类（音色 / 配乐 / 念白）各为独立编号空间，互不影响。
> **角色音色**用于把一段音频指定给某个角色（给 LLM 的描述为 `音色A = {角色名}音色`）；**一个角色只能被一个音色占用**（已占用的角色在其它音色里置灰不可选）；角色改名会联动、角色被删除则回退「未指定」。

### 💾 视频保存设置

- `分段保存`（逐段输出接 VHS）/ `拼接保存`（合并为一段再输出），仅影响下游 VHS
- **分段视频自动保存**：每段跑完立即 ffmpeg 落盘 mp4，不依赖下游 VHS，中途崩溃不丢已生成段落
- **分段视频自动合并**：把落盘的各段按顺序拼成完整视频（未开自动保存时临时落盘，合并后清理）

## 五、采样与解码

- **采样分类**（🎭 采样解码设置顶部，二选一）：
  - **常规采样**（默认）：`res_multistep` / `euler` 等 K 采样器 + 可选「二次采样」（一采 → latent 放大 → 二采）
  - **SelfLift采样**：低分辨率前缀 → 提升到全分辨率 → 收尾（免训练加速），**自动替代二次采样**。参数：
    `采样步数`（独立配置，默认 8 = 低分辨率 6 + 高分辨率 2，与常规采样的 4 步互不干扰）/
    `低分辨率步数` / `低分辨率缩放` / `修正比例 rho` / `修正强度下限·上限` / `放大模型` / `放大后卸载` / `高分辨率分块`。
    H3 建议起点 `rho=0.6`；**修正强度默认对齐上游 SelfLift 节点：下限 `0.5`、上限 `1.0`**。`rho` 与「放大模型」自动联动：**选了外部放大模型 → `rho` 置 0**
    （只用 latent 提升、跳过 VAE 往返，实测过渡 41s → 1.7s）；**放大模型 = `none` → `rho` 回到 0.6**。
    手动改过 `rho` 后不再自动覆盖，此时面板会提示推荐组合。采样器固定标准 `euler`，NFE 数不变。
    > 放大模型只在**过渡**阶段调用一次（低分辨率 → 高清）；其后 `高分辨率步数` 那几步就是**二采**，
    > 因此「高分辨率分块」与常规采样的「空间分块」解决的是同一件事。
    >
    > ⚠️ **`高分辨率分块` 与「分段衔接」的组合**：两者可以共存，但依赖内置 `vendor_selflift/h3_tiling.py` 的
    > **本地补丁**（标记 `JZL_LOCAL_PATCH_TILE_KEYFRAME`）。上游原版在「分段衔接 keyframe + 参考素材 + 分块≥2 块」时会因
    > cond 行数不匹配直接崩（`shape mismatch: value tensor of shape [N, 96] ...`）。
    > 若你按该文件顶部说明用上游新版覆盖了 `vendor_selflift/`，补丁会消失——此时节点会**自动关闭本次「高分辨率分块」**
    > 并在日志告警（不会静默崩，但显存占用会变高）。恢复方式：重新套用补丁后重启 ComfyUI。
- **二采空间分块**（🎭 采样解码设置 → 二次采样 → `空间分块`，三选一勾选）：把二采的一次前向**沿空间长边切块**、
  逐块前向、再按**升余弦窗**加权融合回整画布，用来把放大后的高分辨率二采塞进显存。
  - `关闭`（默认）：整画布二采。
  - `自动`：按 ComfyUI 报出的可用显存挑最省显存的块数（显存够就不分块）。
  - `手动`：固定 `分块数`（2~8）。`分块重叠像素` 默认 128（= 每侧 4 个网格格，相邻两块实际重叠约 8 格），
    在 `自动` / `手动` 下都可调，`关闭` 时该行隐藏。
  - 只作用于**二采**（一采恒为整画布）；放大环节不变——分块解决的是「放大后画布太大采不动」。
  - 音频**不参与**分块（每块都喂完整音频，各块给出整条音频的预测后等权平均）。
  - 自研实现，只依赖 ComfyUI 的 `DIFFUSION_MODEL` / `PREPARE_SAMPLING` 扩展点，因此与**任意采样器**兼容，
    也与 `denoise mask` 安全共存（检测到 mask 时自动退回整画布）；分块内部一旦出错会打印一行警告并**自动退回整画布**，不会中断渲染。
- 解码：视频 `XB-BOX - VAE解码（原版优化）`；音频 `VAE解码（音频）`
- **解码前清理** `卸载显存模型`：每段解码前先 `unload_all_models` 把采样模型退回内存、腾显存给 VAE 解码（对齐 XB-BOX；代价是下一段要重载模型，分段越多越慢）；`不做清理` 则跳过
- **逐段顺序生成**：每段「采样 → 解码 → 写入总线 →（可选落盘）」完成后才进入下一段

> 「🎛️ 运行参数设置 → 语义修正」：勾选后启用**语义桥**，对文本条件做蒸馏学生网络混合修正，增强语义结构与提示遵循度（适配器放 `models/semantic_bridge/`，推荐 `alpha=0.10`）。

| 节点 | 内容 | 顶部按钮 |
|---|---|---|
| JZL - 🎬 生成视频查看器 | 2 列多宫格缩略图，点击预览播放 | 🔄 刷新目录 / 📋 复制剧本 / 📖 编辑剧本 / 📁 输出目录 |

- 故事下拉首项为 **✨ 自动识别**（跟随导演台故事名）；也可手动选择 `output/jzl` 下已有的其他故事。

## 七、常见问题

- **没生成视频，只有分段？** 检查 CLIP / VAE / model 是否接好；含视频或音频参考还需接 `audio_vae`。
- ⭐ **报 `too many values to unpack (expected 3)` / 提示「本段未落盘任何视频」？** 多为**视觉 / 音频 VAE 接反**（两者外形相同）。节点会在编码 / 解码前点名报错并显示检测到的 VAE 类型，按提示换口即可。
- **落盘失败怎么查？** 控制台给出 `❗落盘失败原因` + `❗环境自检报告`（在 `output/jzl/_诊断/`），把报告发回即可定位；也可运行 `python custom_nodes/ComfyUI-JZL-MiniMax-H3/jzl_diagnose.py` 查看环境。
- **ffmpeg 不可用？** 按 `imageio-ffmpeg 自带 → PATH → 常见安装目录` 查找，都找不到时自动改用 PyAV 编码（同样 H.264 + AAC）；「拼接保存」仍需要 ffmpeg，缺少时会保留各分段视频。
- **50 系显卡（sm120）报 `memory_efficient_attention_forward` / `capability <= (9, 0)`？** xformers 的 cutlass attention 未编译 sm120，与本节点无关；节点已自动回退 PyTorch SDPA。若仍报错：改用 `pytorch attention` 后端 / 启动加 `--use-pytorch-cross-attention` / 卸载 xformers。
- **视频数量改了没生效？** 确认「剧本拆解配置」参数已保存；随机种子每次运行都会重跑。
- **开启「Nodes 2.0」（`Comfy.VueNodes.Enabled`）后节点被内容撑得超长、右侧没有滚动条？** 已修。
  - 成因：新版渲染把每个 widget 排进 CSS grid 的一行，**DOM widget 所在行高是 `auto`**（前端按
    `hasLayoutSize = typeof computeLayoutSize === 'function'` 判定），`auto` 行高 = 内容最大高度；而容器内
    的滚动区因祖先链全为 `min-height:auto` 拿不到固定高度 ⇒ 内容越长节点越高、滚动条永不出现。
  - 修法：`🎬 生成视频查看器` / `📝 生成剧本查看器` 的显示窗按节点高度标定一个 `max-height` 上限
    （标定的是与内容无关的「标题+输入行+内边距」高度），让 `auto` 行有界 → **滚动条回到显示窗自身**。
  - **开关「Nodes 2.0」时查看器会"弹"一下（先变长再缩回）？** 已修。切换时前端会整块卸载/重建节点的
    DOM，在「重建完成 → 我们重新写上 max-height」这段窗口里内容（长剧本 / 视频宫格）会先按无上限铺开一帧。
    现在用 `MutationObserver` 监听节点 DOM 的增删（其回调在**绘制前**执行）同步重算，并且
    `--node-height` 读不到时**不写** `calc()`（早期写法带 `3000px` 兜底，会真的把容器撑到 2850px）。  - **开关「Nodes 2.0」时导演台节点被拉得很长？** 已修。面板高度写的是
    `calc(var(--node-height) - K)`，而 `--node-height` 只有 2.0 的渲染器才会写；关掉 2.0 后这个变量消失，
    `calc()` 就回落到兜底值 `3000px` ⇒ 面板 ~2850px 高、把节点撑长。现在 `bindDomWidgetMaxHeight`
    会记住绑定时的行内原样，检测到 `.lg-node` 不存在（经典模式）就**原样还原**（高度回 `100%`），
    并用 500ms 轮询跟上运行时切换（切回 2.0 再自动接管）。  - 导演台节点**整面板不出滚动条**：面板高度 = `节点高度 − 实测的固定 chrome`（同时给 `height`，
    不是只给 `max-height`，否则 flex 拿不到确定高度、提示词框会按内容高度分配空间，把资产窗/重拍条挤出
    可视区 → 面板右侧冒滚动条）。空间不足时**只压缩提示词编辑框**（它自己内部滚动），按钮区、
    「🔄 重拍模式」始终贴在节点下边缘。节点高度 ≥ 460 时实测无面板滚动条；再矮才会退化成面板滚动
    （否则按钮/重拍条够不着）。
- **二采 / SelfLift 高分辨率阶段显存不足（OOM）？** 打开「🎭 采样解码设置 → 二次采样 → 空间分块」选 `自动`
  （常规采样），或勾上 SelfLift 的「高分辨率分块」。分块会牺牲一点速度（每块都要算一遍完整音频）换显存。
  > 无限时长节点（🎭 采样解码设置 →「无限时长衔接⚠实验性功能」；短剧导演台无此功能）时两者只能二选一：**要么用常规采样的「空间分块」，要么用 SelfLift +「高分辨率分块」**
  > （后者需要 `vendor_selflift/h3_tiling.py` 的本地补丁在位，见上文说明）。
- ⭐ **参考图片有效、但音色（参考音频）完全无效？** 检查加载的 diffusion 模型是不是 **`fl2va` / `t2va` 变体**。
  H3 的 `t2va` / `fl2va` / `ref2va` 是同一套 DiT 的**三个任务变体**：
  - `t2va` / `fl2va`：打包序列是 `[text | cond rows(首尾帧) | audio | video]`
  - `ref2va`：打包序列是 `[text | reference blocks(参考图/视频/音频) | audio | video]`

  参考**图片**同时通过 tokenizer 的视觉嵌入进入文本流，所以在任何变体上都"看起来生效"；而参考**音频**在
  tokenizer 里只有一个 `<Audio N>: ` 文本标签、没有任何嵌入，**完全依赖 ref2va 的 reference blocks** →
  加载 fl2va / t2va 时音色必然完全无效，且不报错。请换用文件名含 **`ref2va`** 的模型
  （如 `minimax_h3_ref2va_pruned_int8_convrot.safetensors`）。节点会在有音色参考时自动检测并给出警告。
